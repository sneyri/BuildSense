# Аудит сборок BuildSense (режим «Машиностроение»)

Дата: 2026-10-29. Проверялось: `js/mech/mechAssembly.js`, `mechModel.js`, `mechIO.js`, `mechGeometry.js`, `mechApp.js`, макрос `freecad/import_parts.FCMacro`.
Пользовательские файлы не трогались: тесты строят проекты в памяти, временные файлы лежат в папке ОС / scratchpad.

## Словарик (для не-механика)

| Слово | Простыми словами |
|---|---|
| **Сборка** | Несколько деталей плюс правила, как они связаны |
| **Сопряжение** | Одно такое правило: «оси совпадают», «грани прижаты», «между гранями зазор 5 мм» |
| **Закреплённая деталь** | «Стол»: от неё отсчитываются положения остальных |
| **Степени свободы** | Сколько способов ещё есть сдвинуть/повернуть деталь. Нет свободы = положение определено полностью |
| **Грань, уступ, торец** | Плоские кольца и концы деталей, к которым «прижимают» другие детали |
| **Решатель** | Код, который по правилам сам ставит детали на места |
| **Пересечение** | Две детали занимают одно и то же место (в жизни так не бывает) |
| **STL / STEP / FCStd** | Файлы: сетка из треугольников / обмен твёрдыми телами / родной файл FreeCAD |

## 1. Краткий вывод

Сборки **работают по-настоящему**, а не только на экране. Сопряжения хранятся как правила, решатель сам расставляет детали, при изменении размеров детали переезжают, при невозможных сочетаниях программа говорит «ошибка/конфликт/нет контакта» (а не рисует успех). Всё это подтверждено автотестами, реальным FreeCAD 1.1.4 и независимой проверкой в Blender.

Найдено и исправлено **5 дефектов** (0 × P0, 0 × P1, 2 × P2, 3 × P3). Остаются **ограничения** (раздел 10): в FreeCAD сопряжения не становятся живыми зависимостями, номер уступа привязан к порядку ступеней, типов сопряжений всего три.

## 3. Что работает частично

| Функция | Ограничение |
|---|---|
| Номера граней вала (`step1`, `step2`…) | Привязаны к **порядку ступеней**, а не к физической грани. Удалили первую ступень → сопряжение «перепривязывается» к другой грани. В проверенном случае это обнаружилось (`nocontact`/`broken`), но случайное «совпадение» молча дало бы «ок» (не гарантируется) |
| Проверка пересечений | По профилям тел вращения **без отверстий** (так и написано в сообщении). Проверено по `common()` FreeCAD: 1388,0602 против 1388,0604 мм³ (демо-пересечение), но отверстия фланца не учитываются |
| Степени свободы | Показываются как статусы («закреплён / определён / недоопределён / свободен»), а не числом. Вращение круглой детали вокруг своей оси не ограничивается и в статусе отдельно не считается |
| Экспорт во FreeCAD | Детали, положения, контейнер сборки (`App::Part`) — да. Сопряжения хранятся как **текст-свойство** (`BuildSenseMates`), живыми зависимостями FreeCAD не становятся |

## 4. Что не работает / не реализовано

- Типов сопряжений три (оси, плоскости, смещение) + «закрепить». Нет угла, касания, вращательного/цилиндрического шарнира, сопряжения по отверстиям фланца и боковым поверхностям.
- Нет итеративного решения замкнутых цепочек (решатель идёт последовательно от закреплённого компонента). Сценарии с контурами сопряжений **не тестировались** (см. раздел 10).
- Перемещение мышью в сборке заблокировано (сделано намеренно, положение задают сопряжения).

## 9. Экспорт в FreeCAD — отдельный вывод

**Геометрия экспортируется корректно:** тела валидны, по одному на деталь, объёмы совпадают с формулами до 1e-5 %, габариты и поворот верны, отверстия сквозные, STEP читается обратно, FCStd переоткрывается. Положения деталей совпадают с решением сборки (QA-1 исправлен).
**Но** сопряжения в FreeCAD **не живые**: изменив размер в FreeCAD, детали сами не переедут. Это упрощённая «сборка-контейнер с готовыми положениями». Проверялся консольный FreeCAD (`freecadcmd`); запуск макроса через меню с окном выбора файла **не проверялся**.

## 10. Ограничения: что нельзя считать реализованным

1. Живые сопряжения в FreeCAD (только положения + текст).
2. Устойчивые идентификаторы граней (сейчас — по номеру ступени).
3. Сопряжения, кроме трёх видов; допуски, посадки, прочность, кинематика.
4. Замкнутые контуры сопряжений и избыточные ограничения — не тестировались.
5. Пересечения с учётом отверстий фланца.
6. Не выполнено: проверка в GUI FreeCAD, проверка STL сборки в сторонней программе, нагрузочные тесты (десятки деталей), проверка автосохранения в `localStorage` после перезагрузки браузера.

## 11. Следующие приоритеты

1. Устойчивые id граней (подпись «диаметр/диаметр/положение» вместо номера), чтобы удаление ступени не перепривязывало сопряжение.
2. Тесты и поддержка замкнутых контуров и избыточных сопряжений.
3. Передавать сопряжения во FreeCAD как настоящие зависимости (или хотя бы пересчитывать положения макросом).
4. Больше типов сопряжений: угол, касание, соосность по отверстиям фланца.
5. Учёт отверстий в проверке пересечений и тест на сборках с десятками деталей.
