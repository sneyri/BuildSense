# FreeCAD Checker — прототип веб-редактора домов

Учебный прототип: в браузере собирается простой жилой дом из базовых элементов (стены, пол, крыша,
окна, двери), параметры модели проверяются по машиночитаемым правилам, а результат экспортируется
в FreeCAD макросом.

Это **не** аналог AutoCAD/Revit и **не** BIM-система. Геометрия в браузере — обычная 3D-графика
Three.js, а в FreeCAD создаются параметрические CAD-объекты верстака Part (без семантики Arch/BIM/IFC).

**Пошаговая инструкция для пользователя — [TUTORIAL.md](TUTORIAL.md)**: как создать дом, проверить его
по нормам, понять результаты и добавить своё правило СП в JSON.

## Быстрый запуск

Нужно: Python 3.8+, современный браузер с WebGL и интернет (Three.js загружается с CDN jsDelivr).

```bash
python serve.py
```

Откроется `http://localhost:8000`. На Windows можно просто дважды щёлкнуть `start.bat`.

Открыть `index.html` двойным щелчком нельзя: ES-модули и загрузка правил из `data/rules/`
не работают по протоколу `file://`. `serve.py` — обычный `http.server` из стандартной библиотеки,
который дополнительно отключает кэш и отдаёт `.js` с правильным MIME-типом (на Windows это важно).

## Сценарий демонстрации (5–7 минут)

1. **Запуск.** `python serve.py` → в центре 3D-сцена с базовым домом 10 × 8 м. Мышь: ЛКМ — вращение,
   колесо — масштаб, ПКМ — сдвиг. Кнопки «Изо / Сверху / Спереди / Вписать».
2. **Модель данных.** Щёлкните по стене — справа её свойства: `id`, тип, категория, материал, координаты,
   размеры. Список элементов слева строится из той же структуры данных, что и 3D-сцена.
3. **Размеры.** Слева измените длину дома на 12 м: стены, пол и крыша перестроятся, окна и двери
   останутся в своих стенах. Измените ширину окна в правой панели.
4. **Добавление элементов.** Выберите стену → «+ Окно» / «+ Дверь». Кнопка «Стена» добавляет
   перегородку, «Скрыть крышу» показывает её внутри дома.
5. **Проверка норм.** Справа внизу — результаты: PASS 3, NOT VERIFIED 8. Смените климатический подрайон
   на «IА» — высота помещения 2,6 м даст **FAIL** по п. 6.2 СП 55.13330.2016 (нужно ≥ 2,7 м).
   Раскройте карточку правила: требование, допущения модели, статус достоверности и источник.
6. **Честные статусы.** Покажите правило 1:8 по освещённости — NOT VERIFIED, потому что значение сверено
   только со старой редакцией документа, и демо-правила — NOT VERIFIED, потому что это не нормативы.
7. **Сохранение.** «Сохранить JSON» → «Новый дом» → «Открыть…» (или перетащите файл в окно) — проект
   восстановлен. Готовые примеры лежат в `examples/` (`demo-house-issues.project.json` — дом с замечаниями).
8. **FreeCAD.** «Экспорт в FreeCAD» → в FreeCAD: Макрос → Макросы… → `freecad/import_house.FCMacro`
   → выбрать скачанный `*.freecad.json` → сохранить `.FCStd`. В дереве FreeCAD — группы «Стены», «Полы»,
   «Крыши», «Окна», «Двери»; размеры стен меняются в свойствах `Length / Width / Height`.

## Структура проекта

```
index.html                  разметка: слева параметры и элементы, в центре 3D, справа свойства и нормы
css/style.css               стили
js/main.js                  точка входа: связывает модель, сцену и панели (изменение → commit() → перерисовка)

js/model/placement.js       геометрические расчёты по данным модели (без Three.js)
js/model/metrics.js         расчёт проверяемых параметров модели (высота помещений, этажность, …)
js/scene/sceneView.js       Three.js: рендерер, камера, OrbitControls, свет, выбор мышью
js/scene/geometryBuilder.js построение 3D-геометрии из элементов модели
js/ui/*.js                  панели интерфейса (параметры дома, список, свойства, результаты проверки)
js/io/projectIO.js          сохранение/загрузка JSON, проверка структуры файла, автосохранение
js/rules/ruleLoader.js      загрузка правил из data/rules
js/rules/checker.js         проверка правил → PASS / FAIL / NOT VERIFIED
js/export/freecadExport.js  экспорт модели в JSON для FreeCAD (мм, мировые координаты)
data/rules/                 машиночитаемые правила (index.json + файлы правил)
freecad/import_house.FCMacro макрос FreeCAD: JSON → объекты Part → .FCStd
examples/                   примеры проектов и файлов экспорта
tests/                      автотесты (Node.js и Python)
tools/make-examples.js      пересоздание файлов в examples/
serve.py, start.bat         локальный сервер
```

Модули модели, правил и экспорта не зависят от Three.js и браузера — поэтому они тестируются в Node.js.

## Модель проекта

Проект хранится отдельно от Three.js — 3D-сцена только отображает эти данные. Единицы — метры и градусы,
ось Z направлена вверх (как в FreeCAD).

```json
{
  "format": "freecad-checker-project",
  "version": 1,
  "name": "Дом 10×8",
  "units": "m",
  "settings": { "climateRegion": "2V", "housingFund": "private" },
  "house": { "length": 10, "width": 8, "wallHeight": 2.8, "wallThickness": 0.4, "floorThickness": 0.2,
             "roofType": "gable", "roofSlope": 30, "roofOverhang": 0.4, "roofThickness": 0.25 },
  "elements": [
    { "id": "wall-1", "type": "wall", "name": "Наружная стена — юг", "category": "exterior",
      "material": "brick", "shell": "south",
      "position": { "x": 0, "y": 0, "z": 0 }, "rotation": 0,
      "size": { "length": 10, "thickness": 0.4, "height": 2.8 }, "params": {} },
    { "id": "window-1", "type": "window", "name": "Окно 1", "category": "exterior",
      "material": "pvc_window", "hostId": "wall-1",
      "position": { "offset": 1.5, "elevation": 0.9 },
      "size": { "width": 1.5, "height": 1.4 }, "params": {} }
  ]
}
```

| Тип | Координаты `position` | Размеры `size` | Параметры |
|-----|----------------------|----------------|-----------|
| `wall` | начало стены `x, y, z` + `rotation` вокруг Z | `length, thickness, height` | категория: наружная / внутренняя |
| `floor` | угол `x, y, z` + `rotation` | `length, width, thickness` | пол 1-го этажа / перекрытие |
| `roof` | угол с учётом свеса `x, y, z` + `rotation` | `length, width` | `params.roofType` (gable/flat), `slope`, `thickness` |
| `window`, `door` | относительно стены `hostId`: `offset` вдоль стены, `elevation` от низа стены | `width, height` | — |

Элементы с полем `shell` связаны с параметрами дома: при изменении габаритов слева они перестраиваются.
Ручное изменение размеров такого элемента снимает связь.

## Строительные правила (`data/rules/`)

`index.json` перечисляет файлы правил. Каждое правило содержит:

| Поле | Назначение |
|------|------------|
| `id` | уникальный идентификатор правила |
| `document.id`, `document.title` | идентификатор и название документа |
| `clause` | номер пункта |
| `requirement` | описание требования |
| `parameter` | проверяемый параметр модели (см. `js/model/metrics.js`) |
| `operator` | `>=`, `>`, `<=`, `<`, `==`, `!=`, `between`, `in`, `not_in` |
| `value`, `unit` | пороговое значение и единица (`m`, `mm`, `cm`, `m2`, `deg`, `ratio`, `%`, `count`) |
| `applicability` | условия применимости: `conditions` по параметрам проекта/элемента, `elementType` для поэлементных проверок |
| `modelAssumptions` | какие упрощения модели влияют на проверку |
| `source` | источник (название, ссылка, дата обращения) |
| `verification.status` | `verified` — сверено с текстом документа; `unverified` — требует проверки; `demo` — демонстрационное |

**Как работает `checker.js`.** Для каждого правила проверяются условия применимости; неприменимые правила
показываются в свёрнутом списке «Не применимо». Для применимых:

- **PASS / FAIL** — только для правил со статусом `verified`;
- **NOT VERIFIED** — правило `unverified` или `demo` (сравнение выполняется, но показывается лишь «справочно»),
  либо в модели нет данных для параметра (например, площадей комнат — помещения не моделируются).

### Текущие правила

| Правило | Требование | Статус | Почему |
|---------|------------|--------|--------|
| СП 55.13330.2016, п. 1.1 | не более 3 надземных этажей, высота не более 20 м | verified | сверено с текстом Изменения № 2 (2023) |
| СП 55.13330.2016, п. 6.2 | высота комнат и кухни ≥ 2,7 м (подрайоны IА, IБ, IГ, IД) / ≥ 2,5 м (остальные) | verified | сверено с текстом Изменения № 2 (2023) |
| СП 55.13330.2016, п. 6.1 | общая комната ≥ 16 м² (гос. и муниципальный фонд) | verified | сверено; в модели нет комнат → NOT VERIFIED |
| СП 55.13330.2016, п. 9.18 | световые проёмы : площадь пола ≥ 1 : 8 | unverified | сверено только с редакцией 2018 г.; проверка упрощённая |
| DEMO D.1–D.4 | толщина стены, ширина/высота двери, уклон крыши | demo | придуманы для примера, не нормативы |

Важно: в редакции 2018 г. значение 2,7 м по п. 6.2 относилось и к подрайону IIА, Изменение № 2 его исключило.
Это пример того, почему у каждого правила хранится редакция, дата сверки и статус.

Значения сверялись 26.10.2026 по открытым копиям текстов (ссылки — в поле `source` каждого правила).
Для реального проектирования требования нужно проверять по действующей редакции в официальных источниках.

### Как добавить правило

1. Добавьте объект в существующий файл `data/rules/*.json` или создайте новый файл и впишите его в `index.json`.
2. Если нужен новый параметр модели — добавьте его расчёт в `js/model/metrics.js` (`PARAMETERS` и `collectParameters`).
3. Не знаете точного значения или не сверили его с текстом документа — ставьте `"status": "unverified"` или `"demo"`.
4. Обновите страницу: некорректные правила не применяются и перечисляются в панели проверки с описанием ошибки.

## Экспорт в FreeCAD

1. «Экспорт в FreeCAD» скачивает `<имя>.freecad.json`: все размеры в **миллиметрах**, координаты мировые.
2. В FreeCAD (0.20 или новее): **Макрос → Макросы…**, укажите папку `freecad/`, выберите `import_house` → **Выполнить**.
   Ссылка «макрос .FCMacro» в верхней панели приложения скачивает этот же файл.
3. Выберите JSON. Макрос создаст документ и предложит сохранить его в `.FCStd`
   (можно отказаться и сохранить позже через **Файл → Сохранить как…**).

Что создаётся:

| Элемент | Объект FreeCAD |
|---------|----------------|
| стена | `Part::Box`, из которого цепочкой `Part::Cut` вырезаны проёмы |
| пол, плоская крыша | `Part::Box` |
| двускатная крыша | `Part::Wedge` (треугольная призма) |
| окно, дверь | `Part::Box` — условный блок окна / дверное полотно, плюс скрытый вырез |

Все объекты параметрические: размеры и `Placement` меняются в панели свойств, модель пересчитывается.
У каждого объекта есть свойства группы «FreeCADChecker» (`CheckerId`, `CheckerType`, материал, категория) —
по ним видно, из какого элемента веб-модели он получен. Это CAD-геометрия, а не BIM-модель: для IFC/BIM
объекты нужно отдельно преобразовать в объекты Arch/BIM.

Без интерфейса (консольный FreeCAD):

```bash
FREECAD_CHECKER_JSON=examples/demo-house.freecad.json FREECAD_CHECKER_OUT=house.FCStd FreeCADCmd freecad/import_house.FCMacro
```

## Тесты

```bash
node --test "tests/*.test.js"
```

```bash
python tests/test_macro_mock.py
```

- Node.js (без зависимостей): модель проекта, сохранение/загрузка, расчёт параметров, `checker.js`,
  корректность файлов правил, экспорт.
- Python: макрос запускается с заглушками модулей `FreeCAD`/`Part`, проверяются созданные объекты,
  вырезы проёмов, контур стен и ориентация крыши. **Это не замена запуску в настоящем FreeCAD** —
  макрос стоит один раз проверить в установленном FreeCAD перед демонстрацией.

Пересоздать примеры: `node tools/make-examples.js`.

## Работа без интернета

Three.js подключается с CDN (`index.html`, блок `importmap`). Для офлайн-демонстрации скачайте заранее
`three.module.js` (из `three@0.160.0/build/`) и `OrbitControls.js` (из `three@0.160.0/examples/jsm/controls/`)
в папку `vendor/` и замените адреса в `importmap` на локальные:

```json
{ "imports": { "three": "./vendor/three.module.js", "three/addons/controls/OrbitControls.js": "./vendor/OrbitControls.js" } }
```

## Ограничения прототипа

- Один «коробочный» дом: нет помещений, лестниц, фундаментов, многоскатных крыш; этажность определяется по уровням полов.
- Проёмы — прямоугольные, только в прямых стенах; пересекающиеся проёмы отмечаются как замечание к модели.
- Проверки норм упрощены (см. `modelAssumptions` в правилах) и не заменяют экспертизу проекта.
- Нет отмены действий (Ctrl+Z); последний проект автоматически сохраняется в браузере (localStorage).
